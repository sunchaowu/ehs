## 1. 目标

需求人员在会话里提出需求。平台按软件工程知识生成方案和设计，把设计编译成项目自己的服务代码和镜像，在独立的在线测试环境中验证，经发布确认后调度到已登记服务器。运行中的已知故障由运维智能体自动处理。需要改业务代码时，另开变更草稿，再次经过方案确认、在线测试和发布确认。

平台支持私有部署，面向企业内部频繁变更。第一版交付 OA 领域包。WMS、MES、TMS、APS 使用同一种领域包结构，不在第一版展开内容。

## 2. 已确认决策

1. 运行时自研，参照 DeepSeek Harness 的插件、会话、工具和提示词装配方式。
2. 标准能力是菜单、页面、数据、流程和权限。复杂逻辑才生成受控扩展，并打进该项目镜像。
3. 方案确认一次。确认后自动完成设计和开发，并在候选版本上做在线测试。发布到服务器前再确认一次。`test.requirePassBeforePublish` 默认为真：当前候选没有一次全部通过的测试记录时，不能确认发布。
4. 一个项目是一个逻辑微服务，也是授权模型中的应用程序。
5. 默认一个项目独占一个容器。用户可以把项目放进已有容器组。
6. 每个项目编译出自己的服务模块和依赖。容器组再把一个或多个模块打成一个镜像。
7. 平台自己调度。控制面管理已登记服务器，节点代理运行容器。
8. 管理员的对话记录互相隔离。同一项目的草稿共享。
9. 本地大模型通过模型配置接入，协议是 OpenAI Chat Completions 兼容接口。
10. 日常故障自动修复。更换已发布版本、回退、超出节点池扩容、删除数据和修改权限需要确认。
11. 系统运行服务器、测试服务器、正式服务器分开部署。测试节点池不能回落到正式节点池。测试区与正式区之间不设路由。

## 3. 范围

第一版包括：

- 账号密码登录、注册、微信开放平台网站应用扫码登录。
- 门户布局、个人配置、平台管理员的系统配置、插件配置和模型配置入口。
- 项目、菜单、角色、授权、会话隔离、方案草稿和变更草稿。
- 设计编译、镜像构建、私有镜像库、节点接入、容器调度、发布确认。
- 候选版本的在线测试：自动创建案例、黑盒与白盒、界面元素定位、界面自动输入、测试记录回放。
- OA 第一版领域包。
- 运维信号、已知故障自动处置、审计和门户通知。

第一版不包括：

- 企业微信登录、Kubernetes 调度后端。
- WMS、MES、TMS、APS 的菜单、数据和流程内容。
- 考勤设备、薪资、合同、印章、公文、固定资产。
- 需求会话直接修改正在运行的容器。
- 邮件、短信或其他门户以外的通知渠道。

## 4. 总体结构

平台由四部分组成。

**控制面**一直运行。它保存账号、登录态、用户、角色、项目、菜单、授权、方案、设计、会话、测试案例、测试记录、模型配置、插件配置、节点、容器组和发布记录，并负责任务编排。控制面附带私有镜像库。控制面和镜像库的地址写在系统配置中。

**门户**是统一入口。未登录只显示登录页和注册页。登录后左侧是平台标题和导航，右上角是当前用户、语言和配置，右侧是内容区。

**项目服务**是已编译的项目模块。独占容器组时，镜像只含该项目。公用容器组时，一个镜像包含组内全部项目模块，由一个进程按项目编码分发请求。各项目仍使用自己的数据库。

**节点代理**安装在每台已登记服务器上。它拉取镜像，创建和更新容器，并上报心跳、资源、容器状态、项目指标和结构化日志。

一次业务变更的路径是：

1. 需求进入该用户、该项目的会话，工具只修改草稿。
2. 项目管理员确认方案。
3. 平台生成设计，编译项目模块，构建容器组镜像，并生成测试案例。
4. 平台用候选镜像启动独立测试环境，执行黑盒和白盒案例，保存可回放的测试记录。
5. 发布确认页展示设计摘要、镜像版本、测试结果、容器组、同组项目和目标节点。
6. 确认后，控制面写入期望状态。节点代理更新正式容器。
7. 全部目标节点报告健康后，该版本成为已发布版本。门户按已发布授权显示菜单。
8. 节点持续上报。已知故障按第 10 节自动处理。业务代码问题打开新的变更草稿。

### 4.1 网络分区

系统运行、测试、正式分别使用独立服务器。互联网只进入接入区。分区之间默认拒绝，只开放下面写明的方向和端口。管理操作从运维接入区进入，不从互联网进入。

| 分区 | 服务器上运行的构件 | 不运行的构件 |
|---|---|---|
| 接入区 | 反向代理和 Web 应用防火墙 | 门户进程、控制面、数据库、镜像库、Docker、大模型 |
| 系统运行区 | 门户、控制面、系统库、私有镜像库、本地大模型 | 项目正式容器、测试容器、项目正式库、项目测试库 |
| 测试区 | 测试节点代理、测试容器、项目测试库 | 正式容器、项目正式库、镜像推送、大模型 |
| 正式区 | 正式节点代理、正式容器、项目正式库 | 测试容器、项目测试库、`runtime.mode=test`、镜像推送、大模型 |
| 运维接入区 | VPN 和堡垒机 | 业务容器和数据库 |

允许的跨区连接：

- 互联网到接入区只开放 TCP 443。微信回调也只到接入区的回调地址。
- 接入区只把 443 转到系统运行区的门户和控制面回调。接入区不到数据库、镜像库、节点和模型。
- 用户浏览器只访问接入区。浏览器不连接节点、容器和数据库。
- 系统运行区到正式区、测试区只访问各自的项目接口 443。建库连接分别指向 `database.prodAdminUrl` 和 `database.testAdminUrl`，端口只对控制面的建库地址开放。
- 测试节点和正式节点主动连接系统运行区的控制面 443，使用双向证书。服务器不对互联网开放管理端口。
- 测试节点和正式节点只从镜像库拉取，不能推送。推送凭证只放在系统运行区。
- 正式容器只连接本区正式库。测试容器只连接本区测试库。
- 本地大模型只接受系统运行区的调用，不主动连接数据库和节点。
- 运维人员经 VPN 到堡垒机，再进入系统运行区的管理端口。SSH 不从互联网、接入区、测试区或正式区对公网开放。
- Docker 套接字只在节点本机，不进入任何跨区连接。

正式区与测试区之间没有路由。一个节点只能属于正式节点池或测试节点池之一。系统运行服务器不加入这两个节点池。

## 5. 门户与账号

平台用户是唯一登录身份。密码使用 Argon2id 保存。参数放在系统配置中，安装默认值按 OWASP 建议：`password.argon2.memoryKiB` 为 19456，`password.argon2.iterations` 为 2，`password.argon2.parallelism` 为 1。登录状态由控制面签发，保存在服务端会话中。门户 Cookie 为 HttpOnly、SameSite=Lax；门户使用 HTTPS 时同时标记 Secure。停用账号不能登录。

登录方式有两种。

- 账号密码。
- 微信开放平台网站应用扫码。`wechat.appId`、`wechat.appSecret` 和 `wechat.redirectUri` 来自系统配置。未配置时不显示扫码入口，并在登录页说明原因。账号密码登录保持可用。

扫码使用一次性票据。已绑定微信直接登录。未绑定且 `registration.enabled` 为真时，创建本地用户并绑定。一个微信身份只绑定一个用户。票据超时或用户取消时留在登录页，可以重试。`registration.enabled` 默认是真。关闭后只能由管理员创建用户，未绑定微信扫码时提示联系管理员。

安装脚本创建一名初始平台管理员，随机密码只在安装输出中显示一次。

界面语言至少包含 `zh-CN`。可选语言来自 `platform.languages`。个人配置包含显示名、密码、微信绑定和语言偏好。系统配置、插件配置和模型配置只出现在平台管理员的左侧导航。

内容区打开菜单时显示对应项目页面。没有授权菜单时，拥有创建项目权限的人看到创建项目入口，其他人看到联系管理员的说明。

## 6. 项目、会话与授权

### 6.1 项目

创建项目只要求名称。项目编码默认由名称生成：汉字用平台依赖的拼音库转换，多音字取该库的默认读音；拉丁字母转为小写；其余字符删除；词之间用连字符连接。编码最长 63 个字符，并满足 `^[a-z][a-z0-9-]{0,62}$`。冲突时在末尾追加 `-2`、`-3`。用户可以在保存前修改编码。创建者成为该项目管理员。

项目记录所属容器组。新建项目默认创建只含自己的容器组。用户也可以选择已有容器组。

平台管理员，以及被授予「创建项目」的用户，可以创建项目。

### 6.2 身份

- **平台管理员**管理平台配置、节点和镜像库，并指定项目管理员。
- **项目管理员**拥有本项目的会话、菜单、授权、方案确认、在线测试和发布确认。会话、授权和在线测试可以单独授给其他用户。方案确认和发布确认默认只属于项目管理员，也可以单独授出。
- **业务用户**只使用已发布菜单。

### 6.3 授权

一条授权是：主体（用户或角色）× 项目 × 菜单 × 动作。动作是访问、新增、修改、删除。用户的有效权限是直接授权与其全部角色授权的并集。

菜单只属于一个项目，组成一棵树。创建时必填名称。菜单编码规则与项目编码相同，在同一项目内唯一。新菜单默认排在同级最后。

`平台管理员` 是平台级内置角色。其他角色属于项目。

### 6.4 会话与草稿

一条需求会话属于一个用户和一个项目。用户之间看不到对方的对话记录。被授权进入同一项目的人修改同一份草稿，包括菜单、角色、授权和方案。

会话工具只有：

- `create_project(name, code, containerGroup)`：`code` 和 `containerGroup` 可空。
- `add_menu(project, name, parent)`：`parent` 可空。
- `add_entity(project, name, fields)`：字段类型只允许 `text`、`longText`、`number`、`boolean`、`date`、`datetime`、`user`、`ref`。`ref` 必须写明目标数据。
- `add_workflow(project, name, steps)`：步骤类型只允许 `submit`、`approve`、`record`。
- `grant_role(project, principalType, principalName, menu, actions)`：`principalType` 是 `user` 或 `role`。角色不存在时创建。主体是角色时，把菜单动作授给角色；主体是用户时，写入该用户的直接授权。
- `mark_extension(project, name, boundary)`：记录受控扩展的名称和边界。
- `add_test_case(project, method, name, steps)`：`method` 只允许 `black-box` 或 `white-box`。
- `run_tests(project)`：对当前候选版本执行全部案例。候选镜像尚不存在时拒绝并说明原因。
- `replay_test(project, recordId)`：按指定测试记录回放。记录不属于该项目时拒绝并说明原因。

每个实体生成一个列表页和一个表单页。审批任务生成待办页。页面文案使用设计中的名称。OA 第一版模板名称是简体中文。

工具调用必须落在调用人有权管理的项目上。越权调用被拒绝，并向会话返回原因。这些工具不改变已发布版本。`run_tests` 和 `replay_test` 只操作第 8 节的测试环境。

业务导航只读取已发布版本。项目管理员在门户内容区预览草稿。方案确认前可以继续修改当前草稿。确认之后如需再改，创建一条变更草稿。变更草稿必须重新经过方案确认，再编译、在线测试并进入发布确认。当前已发布版本保持不变，直到新的发布确认完成。

一句话可以连续调用多个工具。例如创建项目、两个菜单和一种角色授权，都写在同一份草稿里，并在方案确认前展示给用户。

## 7. 生成、发布与节点调度

### 7.1 设计与编译

方案确认后自动生成设计。设计包含数据、页面、接口、流程、权限、受控扩展边界和容器组。生成器把设计编译成该项目的服务模块和依赖清单。同一次设计重复编译，源码相同。生成源码不包含编译时间、随机数或本机路径。

标准菜单、页面、数据、流程和权限调用平台运行库。设计中标记的复杂逻辑编译到该项目的受控扩展模块。OA 第一版没有受控扩展。

列表、表单和审批待办由标准页面生成。

### 7.2 镜像

编译成功后构建容器组镜像。镜像写入已编译模块和依赖，不写入数据库地址、密钥、模型地址或节点地址。镜像推送到控制面的私有镜像库，用不可变摘要标识，并记录对应的设计修订和源码修订。独占容器组的镜像只包含该项目模块，这个镜像就是该项目的发布镜像。副本是同一镜像的多个容器，业务数据只存放在项目数据库中。

公用容器组发布其中一个项目时，使用组内全部项目的当前已确认模块重新构建镜像。由本次变更所属项目的发布确认人确认。确认页列出同组其他项目，并在确认前向这些项目的项目管理员发送门户通知。确认权不自动交给同组其他项目。

### 7.3 数据

每个项目使用独立的 PostgreSQL 数据库。正式库由 `database.prodAdminUrl` 在正式区创建，测试库由 `database.testAdminUrl` 在测试区创建。系统自身的账号、草稿和审计保存在系统运行区的 `database.systemUrl`，与项目库分开。发布确认后、更新正式容器前，控制面创建尚未存在的正式库。连接信息由该区的节点代理在启动容器时注入。对应数据库服务器未配置或建库失败时拒绝发布，不更新容器，并说明原因。首次发布在容器更新阶段失败时，保留已经创建的空库，项目状态保持未发布，失败原因包含库名。再次发布复用该库。

### 7.4 节点与期望状态

平台管理员登记服务器，并指定它属于系统运行区、测试区或正式区。测试区和正式区的节点通过控制面生成的安装脚本接入，之后从该区主动上报心跳。节点接入后不自动加入节点池。正式节点只能写入 `scheduler.defaultNodePool`。测试节点只能写入 `test.nodePool`。同一节点写入两个池时拒绝保存并说明原因。节点容器运行时第一版是 Docker Engine，套接字或地址只写在该节点本机配置中。

容器组的期望状态包括镜像摘要、目标节点、副本数。副本数默认是 1。未指定目标节点时使用 `scheduler.defaultNodePool`。节点池为空且没有显式目标节点时拒绝发布，并说明原因。节点报告健康是指进程在运行、项目数据库可连接、运行镜像摘要等于期望摘要。

在已有目标节点上增加副本，或把节点加入容器组，都形成新的发布候选，必须经过发布确认。

发布确认前，正式节点上的运行容器不变。取消确认时保留已构建候选和测试记录，不部署。`test.requirePassBeforePublish` 为真且当前候选没有一次全部通过的测试记录时，拒绝发布确认并列出失败案例。确认后代理拉取镜像并更新正式容器。全部目标节点报告健康后，该版本成为已发布版本。任一节点失败时继续运行上一版本，并列出失败节点和原因。第一次发布失败时，项目保持未发布。已发布版本保留，供确认后的回退使用。

控制面本身由仓库中的统一安装脚本部署和启动。

## 8. 在线测试

镜像构建成功后，平台立即对候选版本做在线测试。测试对象是候选镜像，不是已发布版本。

### 8.1 测试环境

测试容器只在测试区启动，使用候选镜像，副本数是 1。它使用测试区的独立数据库，不连接项目正式库，也不连接系统库。测试库由 `database.testAdminUrl` 创建，库名是 `tst_` 加项目编码；超过 63 个字符时截断编码，并且不得与正式库同名。公用容器组的候选镜像仍包含同组模块；测试只为当前项目执行案例，同组其他项目在测试环境中使用各自的空测试库，正式数据不被读取或写入。

测试节点只取自 `test.nodePool`。该池为空时测试不开始，并说明原因，不改到正式节点池。容器仅在环境变量 `runtime.mode` 为 `test` 时开放白盒入口。正式区的期望状态不设置该变量，正式区也不接收测试容器。

每次运行前重建测试库。运行结束、失败或达到 `test.runTimeoutSeconds` 后停止并删除测试容器。测试案例和测试记录保留。

### 8.2 自动案例

编译设计时生成案例。同一设计重复编译，自动案例相同。设计修订更新后，自动案例按新设计重新生成；用户用 `add_test_case` 追加的案例继续保留，直到用户删除。案例编码由方法和步骤内容稳定生成，不使用编译时间或随机数。

黑盒案例从菜单、表单、流程和角色生成界面路径。执行时以对应用户的身份打开门户，定位元素并输入案例中的值。白盒案例调用候选模块的字段校验、流程迁移、接口结果和授权拒绝，不经过界面。白盒入口只在测试容器中存在。

案例没有写明输入值时，创建案例的同时按字段类型写入固定值并保存到案例中：`text` 和 `longText` 使用字段名加「示例」，`number` 使用 1，`boolean` 使用真，`date` 使用 `2000-01-01`，`datetime` 使用 `2000-01-01T00:00:00`，`user` 使用本案例指定角色下的测试用户，`ref` 写明所依赖的前序步骤。运行时使用该步骤创建的记录。用户写明的输入值按原值保存。回放和再次运行都使用案例里保存的值。

### 8.3 界面定位与自动输入

生成页面的每个可交互元素带有稳定标识，格式为 `{项目编码}/{菜单编码}/{字段或动作编码}`。黑盒定位按这个顺序尝试：

1. 稳定标识。
2. 元素角色加可访问名称。
3. 该步骤上一次成功定位时记录的标识。

屏幕坐标可以记入测试记录供查看。回放时重新按上述顺序定位，不靠坐标点击。单步超过 `test.stepTimeoutSeconds` 仍未定位到元素，该步失败并写明已尝试的定位方式。

自动输入把案例中的值写入定位到的字段，然后执行案例中的动作。

### 8.4 记录与回放

每一步测试记录包含：开始时间（精确到秒）、案例编码、方法、候选镜像摘要、定位方式、输入、期望、实际结果、通过或失败。一次运行汇总这些步骤，并给出总结果。

`replay_test` 按记录中的步骤，对当前候选镜像重新执行。黑盒重新定位并输入。白盒使用记录中的接口和参数。结果写成一条新记录，并注明被回放的原记录和原镜像摘要。当前没有候选镜像时拒绝回放并说明原因。

拥有在线测试权限的用户可以在测试环境中手工操作。平台把这些操作录成一条黑盒记录，记录可以再次回放。

测试失败不修改正式容器，也不打开运维处置。用户根据失败记录修改草稿时，走变更草稿、方案确认、重新编译和重新测试。

## 9. OA 领域包与提示词

领域包供需求会话使用。每个包包含术语、角色模板、菜单模板、数据模板、流程模板、测试案例模板和一段会话说明。会话只注入与当前这句话匹配的领域包。

需求会话的提示词有五层：

1. 角色是企业应用分析师，负责方案和设计，不执行发布。
2. 当前项目快照：草稿中的菜单、角色、授权、方案状态；候选版本出现后附带最近一次测试结果。
3. 匹配到的领域包摘录。
4. 第 6.4 节列出的工具。
5. 闸门：方案未确认前只改草稿。`run_tests` 和 `replay_test` 在候选镜像出现后才可用。发布工具不在需求会话中。

工作顺序是先选定领域包，用模板生成最小方案，再按需求人员的原话修改差异。领域包不能表达的能力用 `mark_extension` 标出。与已注入领域包无关的需求，不套用该包的菜单。

OA 第一版是一个项目，默认独占容器组。

- **角色**：员工、部门负责人、人事管理员、行政管理员。
- **菜单**：工作台、部门、员工、发起申请、我的待办、我的申请、请假申请、假期余额、公告。
- **数据**：部门、岗位、员工、假期类型、请假单、审批任务、公告。
- **流程**：请假由员工提交，部门负责人审批，人事备案。备案步骤可以在设计中关闭。另有一条节点可配置的通用审批，供后续申请复用。

员工档案和平台登录用户分开保存。员工可以绑定一个登录用户。绑定后，该用户看到自己的申请和待办。

已发布项目不随领域包升级自动改写。采用新模板通过新的变更草稿完成。

OA 第一版在编译时另外生成这些在线测试案例：员工提交请假、部门负责人审批、人事备案、员工不能执行人事菜单的删除动作、请假单缺少必填字段时被拒绝。前三项是黑盒，后两项是白盒。

## 10. 自动运维

运维智能体与需求会话分开，使用同一份模型配置。它的提示词有四层：运维角色、当前项目或节点的状态快照、已发布版本、本节列出的处置工具。它不注入领域包，也不修改方案和设计。

节点代理上报：心跳、CPU、内存、磁盘、容器状态、运行镜像摘要与期望摘要是否一致、项目请求错误率、延迟、数据库连通性、结构化日志。日志包含项目编码、版本和追踪标识。

安装时写入这些系统配置默认值：

| 配置键 | 默认值 |
|---|---|
| `ops.heartbeatTimeoutSeconds` | 30 |
| `ops.restartMaxAttempts` | 3 |
| `ops.restartWindowSeconds` | 600 |
| `ops.errorRateThreshold` | 0.05 |
| `ops.errorRateWindowSeconds` | 300 |
| `ops.minRequestsInWindow` | 20 |

自动处置限于：

- 容器进程退出，且当前窗口内的重启次数低于 `ops.restartMaxAttempts`。
- 镜像拉取的暂时失败，在同一窗口内重试。
- 数据库连接中断，按重启规则重启容器。
- 节点心跳超过 `ops.heartbeatTimeoutSeconds` 后，把该容器重新调度到同一目标节点池中的其他健康节点，副本数不变。

公用容器组只有在整个进程不可用时才整组重启，并向组内每个项目发送门户通知。某一个项目的业务错误不触发整组重启。

窗口内的请求数达到 `ops.minRequestsInWindow`，且错误率不低于 `ops.errorRateThreshold`，同时进程仍然健康时，打开变更草稿并附上日志和指标。受控扩展抛错、业务规则不符合预期，也按同一方式处理。运维智能体不修改运行中的代码。这样打开的草稿按第 6.4 节重新确认方案，并按第 8 节通过在线测试后，才能进入发布确认。

更换已发布版本、回退、把节点目标扩大到当前节点池之外、删除数据和修改权限，先在门户生成待确认动作。项目管理员确认后才执行。

每次自动动作和每次确认后的动作都写入审计。时间精确到秒，字段包括项目或节点、信号、动作、结果和操作者。自动动作的操作者是运维智能体。

平台管理员查看全部节点。项目管理员只查看本项目的状态、处置记录和待确认动作。通知只出现在门户内。

## 12. 错误处理

| 情况 | 结果 |
|---|---|
| 微信未配置 | 隐藏扫码入口并说明原因，账号密码登录可用 |
| 扫码超时或取消 | 留在登录页，允许重试 |
| 注册已关闭且微信未绑定 | 拒绝创建用户，提示联系管理员 |
| 停用账号登录 | 拒绝登录并说明原因 |
| 项目或菜单编码冲突 | 拒绝保存并说明冲突编码 |
| 会话工具越权 | 拒绝调用并在会话中说明原因 |
| 设计无法编译 | 不生成发布候选，保留上一已发布版本，说明编译原因 |
| 镜像构建或推送失败 | 不改变节点容器，说明失败步骤 |
| 数据库服务器未配置或建库失败 | 拒绝发布，不更新容器，并说明原因 |
| 首次发布在容器更新阶段失败 | 保留已创建的空库，项目保持未发布，失败原因包含库名 |
| 默认节点池为空且未显式选择节点 | 拒绝发布并说明原因 |
| 测试节点池为空 | 在线测试不开始并说明原因，不使用正式节点；在要求测试通过时同时拒绝发布确认 |
| 同一节点同时属于正式节点池和测试节点池 | 拒绝保存并说明原因 |
| 界面元素在时限内无法定位 | 该测试步骤失败，记录已尝试的定位方式；正式容器不变 |
| 当前候选测试未全部通过且要求先通过 | 拒绝发布确认，并列出失败案例 |
| 回放时没有候选镜像，或记录不属于该项目 | 拒绝回放并说明原因 |
| 发布后任一目标节点未健康 | 继续运行上一版本；首次发布则保持未发布，并列出失败节点 |
| 节点池内没有其他健康节点可供重新调度 | 保持期望状态，门户通知项目管理员，不扩大节点池 |
| 重启次数达到上限 | 停止自动重启，门户通知项目管理员 |

失败时给出原因。平台不用匿名访问、跳过确认或改写已发布版本来代替失败步骤。

## 13. 验收

第一版至少覆盖这些行为：

1. 密码注册、登录、停用账号拒绝登录、初始管理员密码只显示一次。
2. 微信新用户在允许注册时绑定并登录；已绑定用户直接登录；关闭注册后未绑定扫码被拒绝。
3. 未配置微信时扫码入口不可用，账号密码登录可用。
4. 普通用户看不到系统配置、插件配置和模型配置。
5. 两名项目管理员看不到对方的对话，同一项目草稿互相可见。
6. 草稿菜单不出现在业务用户导航中；发布成功后按授权出现。
7. 用户直接授权和角色授权取并集。项目管理员不能修改其他项目。
8. 同一设计两次编译结果相同。发布确认前，已发布的正式容器不变；测试容器只运行候选镜像，并在测试结束后删除。
9. 公用容器组的镜像包含组内全部项目模块，各项目数据库不同。
10. 目标节点未全部健康时，已发布版本不变。
11. 在模型配置可用的前提下，说「我要请假审批」时，草稿来自 OA 模板，包含请假流程和规定菜单。与 OA 无关的需求不写入这些菜单。
12. 进程退出会在限额内重启并留下精确到秒的审计。错误率超过阈值时打开变更草稿，不修改运行中的代码。
13. 回退在确认前不改变正在运行的镜像。
14. 候选版本自动生成黑盒和白盒案例。黑盒按稳定标识定位并输入案例中保存的值。测试库与项目正式库不同。
15. `test.requirePassBeforePublish` 为真且存在失败案例时，不能确认发布，正式容器不变。
16. 回放按记录重新执行，并生成一条带精确到秒时间的新记录。
17. 测试容器只出现在测试区。正式区不存在 `runtime.mode=test` 的容器。测试区不能连接正式库。

## 14. 实施顺序

本文是已确认的产品设计。实施时按下列顺序分别制定计划，前一项可运行后再进入下一项，不在一个计划里同时展开六项：

1. 控制面安装脚本、门户、账号、系统配置和模型配置。
2. 项目、会话、草稿、菜单和授权。
3. 设计编译、镜像构建、节点代理和发布确认。
4. 在线测试、自动案例、界面定位与输入、测试记录回放。
5. OA 领域包。
6. 运维信号、自动处置、确认动作和审计。
