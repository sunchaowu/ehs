## 借鉴 cordis 的设计对应

| cordis 概念 | 本平台实现 |
|---|---|
| Bundle 清单（`package.json` + `cordis.patch.yml` 行） | 控制面内置注册表 `definePlugin()`：`id`、`title`、`description`、`configSchema` |
| `apply(ctx, config)` + `ctx.effect` 所有权与清理 | `activate(config)` 返回清理函数；停用、重配、关机时调用 |
| `Config` schema 在激活时校验 | `validatePluginConfig()` 按字段类型与必填校验，缺省值自动补齐 |
| `set_plugin` 与 enabled/disabled/failed 状态 | 行字段 `enabled`（期望状态）+ `status`（实际状态：`disabled`/`active`/`failed`）+ `failure` 原因 |
| 插件状态跨重启持久 | 服务启动时 `activateInstalled()` 恢复期望启用的行，失败保留原因 |
| Plugin Manager 页面 | 门户插件配置页：卡片列表、启停开关、失败原因、配置表单、启停记录 |
| 审计精确到秒 | `plugin_events` 表记录 enable/disable/config 的操作者、结果、原因与时间 |

第一版边界：插件由平台代码内置注册，不动态加载外部包；不预装业务插件；数据库残留行没有对应定义时以「插件定义不存在，无法运行」展示并禁止启用。

## 已实现行为

- 启用插件时按 schema 校验存量配置并激活；激活失败时期望状态保持为启用、实际状态标为 `failed` 并记录原因，下次重启自动重试。
- 停用插件调用清理函数，行回到 `disabled`。
- 保存配置先校验（未知配置项、类型错误、必填缺失都返回原因），已启用插件保存后立即用新配置重新激活。
- 启停与配置修改写入 `plugin_events`，按插入序号倒序返回最近 50 条。
- `GET /api/plugins`、`PUT /api/plugins/:id/state`、`PUT /api/plugins/:id/config`、`GET /api/plugins/:id/events` 全部仅限平台管理员。
- 门户插件配置页带稳定标识 `platform/plugin-config/{页面}/{元素}`，无配置项的插件不渲染表单。
